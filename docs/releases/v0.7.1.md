# v0.7.1: done means done

Two complaints, both of which turned out to be the pet claiming something it
could not know, and one audit of whether the rest of its behaviour makes sense.

## "Done" while five subagents are still running

The card went green whenever the assistant stopped talking. But an assistant
frequently stops talking *because* it is waiting: two subagents are still
reviewing, or a release pipeline it started in the background has not reported
back, and its final sentence says exactly that. `Stop` fires anyway, and **no
hook of any kind fires when a background command or a subagent finishes**. From
the hooks alone, that turn is indistinguishable from a finished one — so the
loudest, most trusted signal in the app was the one it had the least evidence
for.

The transcript has both halves. Claude Code gives every asynchronous thing an
id when it starts it and names that same id again when it completes, so the
work still outstanding is launches minus completions — and the overlay was
already reading that file for the live line.

A card now reads **Finishing · 3 running**, in the working colour with a
blinking dot, until the last one reports back; only then does it turn green.
The same three-way distinction the Claude Code sidebar draws. A count that
never drains, because the overlay started watching after the launch and missed
the completion, is written off after five minutes of silence.

The pet deliberately does not read the assistant's prose looking for "waiting
for" — that is guessing dressed as knowing, and the ids are an exact answer.

## The tray blink is a separate promise

The card is in front of you and can correct itself; a tray blink is a tap on
the shoulder of somebody looking somewhere else, and it cannot be taken back.
So the blink and the unread dot now wait until a completion has held for eight
seconds with nothing still running. A blocking stop hook — a review gate, a
completion loop — vetoing a stop no longer reaches you as a false finish.

And the state the README calls the worst one finally earns the same channel:
**"Needs you" blinks the tray**. Done and Failed always could; the one that is
costing money in real time was the only state that could not reach you behind a
fullscreen window. The sound stays opt-in.

## It was not there after a reboot

The pet did not come back after a restart, and `Ctrl+Alt+P` did nothing —
because the hotkey belongs to a process that was not running. Autostart had
never been switched on: it was a button in a panel shown once, which is a poor
way to decide something an overlay depends on entirely.

- The first run registers it to start with Windows and says so on the welcome
  panel, which states the decision rather than offering a blind toggle.
  Turning it off is recorded and stays off.
- An entry pointing at a path the program no longer lives at is corrected at
  launch. Present, plausible and inert was a second way to lose the pet, and it
  looked identical to the first.
- **Check my setup** gained an "After a reboot" row. A machine that would lose
  the pet at the next restart used to pass with every light green.

## Fixed, from the same audit

- **Clicking a finished card opens it** instead of dismissing it. The moment a
  card holds the most worth reading — the turn is over, the final message and
  the last two dozen actions are right there — was the one moment a click threw
  all of it away, unrecoverably. Dismissal belongs to ×, which is aimed.
- **An urgent card gives the card back.** Something needing you outranks what
  you were reading while it is urgent, and then returns it, instead of
  permanently stealing the slot from the chat you chose to watch.
- **Hiding the cards no longer silences a chat that starts needing you**, which
  the README already promised it would not.
- **`show_bubble` is wired to the thing it documents.** It was stored, loaded,
  saved, and read by nothing, while the real switch was a variable that reset
  on every restart and every reload.
- **One count of outstanding work per card**, from one source. The old chip
  counted only subagents, was never decremented when one ended without an
  event, and drifted upward until it contradicted the rest of the card.
- **A launch with no hooks installed says so once**, rather than dozing
  silently in a way that is deliberately indistinguishable from healthy.

## For working out what it is doing

```bash
pipsqueak sessions        # what the overlay would draw right now, as JSON
pipsqueak autostart on    # also: off, status
```

`sessions` answers "why is that card saying that": a card is a session file
joined to the chat record and the transcript, and both joins were previously
only visible by looking at the pet. Creating `~/.pipsqueak/payloads` makes
every hook keep a copy of its raw payload there until the directory is removed
— a directory you have to make, rather than a setting you might leave on,
because payloads contain prompts.

`tools/simulate.mjs --only <project>` replays one project alone, and the
recorder passes the flag through. The recorder's backdrop is now topmost, so a
transparent overlay cannot photograph the desktop behind it.

## Verified

81 Rust and 31 JavaScript tests, clippy clean. The transcript shapes this
release depends on were captured from real sessions rather than assumed, and
are pinned by tests that fail if Claude Code changes them. End to end against
the real binary: a turn ending with a background command and two subagents
outstanding reports three, then two, then zero, and only the last of those is
Done. Recorded from the running app: the card reading "Finishing · 3 running"
in blue, and the same card green after everything reported back.

Not re-verified on hardware: a fresh install, uninstall, and start-with-Windows
across an actual reboot. macOS and Linux remain untested.

## Two more, found while installing this release

Both were caught by using the build rather than by reading it, which is the
argument for installing your own release before publishing it.

- **Starting the pet again straight after quitting did nothing.** The
  single-instance guard trusts a heartbeat file that is believed for six
  seconds, and a stopped overlay leaves its last one behind — so for those six
  seconds a new launch stood down in favour of a process that no longer
  existed, silently. The heartbeat now carries a pid and is checked against it,
  and quitting takes the file with it. The guard was causing the complaint it
  exists to prevent.
- **`pipsqueak --version` could kill the process instead of answering.** It
  printed directly to stdout, which a GUI-subsystem binary does not reliably
  have — the module's own comment says so about every other command — and with
  `panic = "abort"` a failed print is an abort. It goes through the same safe
  path as the rest now.

## Upgrading

Nothing to migrate. On first run after updating, Pipsqueak registers itself to
start with Windows unless you have already made that decision; the menu and
`pipsqueak autostart off` both undo it.

v0.7.0 was tagged and built but never published: it was missing the two fixes
above, and shipping a release known to mishandle its own restart was not worth
the tidy version number.

# v0.5.0: telling the truth

The largest change since the first release, and almost all of it is about the
same thing: the pet used to state things that were not true, and it stated them
confidently.

## The pet no longer claims a turn is finished when it isn't

`Stop` is not reliably the end of a turn. Claude Code fires it whenever the
assistant yields the floor, which includes cases where it is about to carry
straight on: a scheduled job, a stop hook that asked it to continue, or
background tasks still running. Every one of those used to produce a "Done"
card that then sat there for thirty seconds being wrong.

`Stop` now reads `session_crons`, `stop_hook_active` and `background_tasks` and
holds as running when work continues. A completion that arrives alongside
background tasks settles two seconds late, so a follow-up event can cancel it.

## A crashed session no longer runs forever

Nothing writes a file to report that Claude Code died, and the old cleanup only
ran on `SessionEnd`, which a crash never sends, with a twelve-hour cutoff.

A sweep now runs every ten seconds. A dead agent process retires its session
immediately; work with no events for five minutes drops to idle. Liveness is
`(pid, process creation time)`, never the pid alone, because a reused pid would
otherwise report a dead session as alive. A process we are not allowed to open
falls back to the process table rather than guessing, so a permission error
cannot delete a live session.

## "Waiting" and "done" are no longer stored as states

A single field was answering three unrelated questions: what is the session
doing, how did the last turn end, and is a human blocking it. That is what let
a card strand on "Needs you" when the prompt was answered somewhere the hooks
could not see. They are now separate, and only forward progress moves the
durable state.

## New

- **Cards say what they are blocked on.** `PermissionRequest` is recorded and
  surfaced only once it outlives an 800ms debounce, because auto-mode answers
  most prompts without anyone being asked. The hook writes a file and exits 0
  with empty stdout. It never prints a decision, so it cannot approve or deny
  anything, and Claude Code's own prompt is unaffected.
- **A warning on commands that cannot be undone.** Quote-aware, anchored at
  each shell segment's command position, and display-only: `git commit -m "docs
  && git push --force"` is not a force push, and `--force-with-lease` is not
  flagged.
- **Completions survive not being seen.** A finished turn leaves a mark that
  outlives the thirty-second linger, until you click the card or the project
  starts working again. If the overlay is covered entirely, the tray icon
  blinks.
- **Do Not Disturb** silences the sound and the blink, and the pet visibly
  dozes so you can see that it will not interrupt you.
- **A setup check** (right-click → Setup check) that verifies the hooks are
  registered, that they point at a program that exists, that the session folder
  is writable, and (the useful one) watches for ten seconds while you run
  something, so it can tell "nothing happened" apart from "the hooks are not
  firing". The report is copyable and contains no paths, prompts, or file
  contents.
- **A first run that explains itself**, including installing the hooks without
  going to a terminal. Only on a genuinely new install: if the hooks are
  already registered you get a one-line notice about the new shortcut instead
  of a panel offering to set up something that is already set up.
- **A global keyboard shortcut.** `Ctrl+Alt+P` shows and hides the pet from
  anywhere. Windows gives a chord to whoever asks first, so if that one is
  taken Pipsqueak falls back to the next free one and says which in the
  right-click menu and the setup check. Configurable, and `off` disables it.

## Fixed

- Concurrent hooks no longer discard each other's events. Claude Code runs the
  hooks matching one event in parallel; both used to read the same state and
  the later write won.
- `PostCompact` with `trigger: manual` leaves the session idle. An automatic
  compaction happens mid-turn and resumes.
- A `Task` tool call counts as a subagent launch, often the only signal one
  happened.
- A permission prompt no longer survives being answered. Claude Code runs
  `PreToolUse` before raising `PermissionRequest`, so a `PreToolUse` arriving
  afterwards means the tool is running. The card used to keep asking about a
  command that had already been approved.
- One failing tool no longer turns the whole card red. Claude nearly always
  tries something else; it is now a mark on the turn.
- Uninstalling removes the hooks. They named the executable by absolute path,
  so uninstalling used to leave fifteen entries pointing at a deleted file.
  Upgrading leaves them alone, since an upgrade runs the old uninstaller first
  and the hooks there are still correct.
- The overlay cannot be stranded off-screen by undocking or unplugging a
  monitor.
- A corrupt `config.json` is backed up rather than overwritten, one bad value
  costs only itself, and a config written by a newer version is never rolled
  back.

## Other

- Frames have individual durations, so the loops read as breathing rather than
  as a metronome. The atlases are unchanged.
- The canvas stops animating after five seconds on a resting loop, at the top
  of a cycle. An overlay meant to be left running should not composite a frame
  every 16ms over a video.
- Hit testing polls faster the nearer the cursor is to something clickable.
- Tests: 39 Rust, 23 JavaScript. `npm test` and `cargo test`.
- The README animation is recorded by `npm run demo`, which paints its own
  backdrop and drives the app with simulated sessions. Reproducible, and it
  cannot accidentally publish somebody's desktop.

## Upgrading

The window is taller than it was to fit the setup panel, and the saved position
is migrated to match, so the pet stays where you left it. `config.json` gains a
`version` field.

Re-run **Reinstall Claude Code hooks** after updating, then restart Claude Code
so it picks them up.

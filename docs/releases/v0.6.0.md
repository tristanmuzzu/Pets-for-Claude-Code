# v0.6.0: holding still

A deep audit of the whole codebase, provoked by one complaint: things popped
up in the corner of the screen and vanished again before they could be read.
That turned out not to be one bug. It was five, stacked, plus a family of
races feeding them. This release is almost entirely fixes; the full ledger,
with the mechanism of every finding at the line it lived on, is in
`FINDINGS.md`.

## The flicker, by mechanism

- **Every clean `Stop` now settles for two seconds.** A blocking stop hook —
  a review gate, a completion loop — can veto a stop and have the turn carry
  straight on, and `stop_hook_active` only admits that on the *second* Stop.
  Zero settle time meant every vetoed stop flashed a Done card that the next
  tool event wiped. If you run stop hooks, this was most of what you saw.
- **A settling turn stays on screen.** The settle window that already existed
  wrote `state: "idle"` alongside the outcome, and the overlay took the card
  out of the DOM for the whole window, then popped it back in as Done. The
  anti-flicker hold was itself the flicker.
- **The watchdog asks before it reloads.** Windows throttles timers for an
  occluded window down to about once a minute, which read as "the page is
  dead", so the overlay hard-reloaded — blanked and repainted — every minute
  under anything fullscreen. Silence now earns a ping, which throttling does
  not delay, and only a page that will not answer is reloaded. `pipsqueak
  control show` follows the same rule instead of reloading unconditionally.
- **Cards keep their place.** Moving a card in the stack replayed its
  entrance animation from transparent — a visible blink every time a card was
  promoted. The entrance now plays once, on genuinely new cards only.
- **A notice is not a session.** The update notice used to take a card slot,
  which collapsed the whole stack to one-line mode for six seconds and blinked
  the tray, minutes after launch, on a timer nobody asked for.

## The races underneath

- `SessionEnd` deleted the session file without holding the lock every other
  hook holds. Claude Code runs hooks detached and in parallel, so a straggler
  could resurrect the file as a zombie card that the sweep then killed.
  Deletion is locked now, and only the events that genuinely begin work may
  create a session file.
- The sweep did lock-free read-modify-writes against files hooks were
  writing, deleted sessions it merely failed to *read* (antivirus scanners
  hold freshly renamed files for a moment), and treated a failed process-table
  snapshot as "every process is dead". Each of those deleted a live session
  that the next event recreated as a brand-new card.
- Two overlays could end up running at once — launch during the boot gap, or
  after a resume — stacking two pets that fought over the same command file.
  The heartbeat now exists before anything can race it, and a second launch
  wakes the first instead.
- The tray and the pet menu each kept their own idea of the config and
  silently reverted each other's changes. They now agree, checkboxes included.

## Smaller truths

- A turn ending clears "Needs you": a denied permission followed by the end
  of the turn no longer leaves the card demanding attention for hours.
- Auto-compaction mid-turn (`SessionStart` with `source: "compact"`) no
  longer resets a working card to "Session started" and steals its headline.
- A subagent's inner monologue stays off the parent card's live line.
- An emoji in a chat title no longer silently costs the whole title.
- Two chat records claiming the same session resolve to the newest one,
  deterministically — the title cannot swap every rescan, and **↗** opens the
  chat the title names.
- `git branch -D` and `git branch -d` are different flags: the safe one is no
  longer badged as irreversible. One level of `cmd /c` / `powershell
  -Command` / `bash -c` wrapping is unwrapped, so the common Windows shapes
  of a dangerous command are still seen.
- A project living under `D:\Temp` is a project, not a scratch session, and a
  git submodule no longer hides which repository owns it.
- `pipsqueak control stop` stops the process, matching the menu's "put it
  away" / "stop it" split. `off` and `hide` still just hide.

## The installer and the machinery

- `~/.claude/settings.json` comes back the way it was found: key order
  preserved (it used to be alphabetised on every run), no rewrite and no
  fresh backup when nothing changed, no empty `hooks` object planted by an
  uninstall that found nothing to remove. Backups are pruned to the newest
  five.
- Log rotation could abort the entire overlay when the file's byte midpoint
  landed inside a multibyte character — em dashes are logged today, and the
  release profile turns that panic into a process kill. It cuts at a line
  boundary now, in bytes.
- The setup check compares hook paths the way Windows does (case and slash
  direction do not make two copies), and traffic that stopped an hour ago
  warns instead of reading green.

## Verified

76 Rust and 28 JavaScript tests (nine new regression tests pin these fixes),
clippy clean. End-to-end on the release binary against a sandboxed profile: a
straggler event for an ended session creates nothing; prompt → permission →
stop leaves a two-second settle and a cleared waiting flag; mid-turn
compaction keeps the headline. The demo pipeline recorded the real app
running simulated sessions without a blank frame.

Not re-verified on hardware for this release, per the checklist: fresh
install and uninstall round-trip, start-with-Windows across a reboot, and the
second-monitor unplug. Nothing in this release touches autostart; the
installer changes are covered by tests but not by a fresh-machine install.
macOS and Linux remain untested.

## Upgrading

Nothing to migrate. The hooks are unchanged in shape; a reinstall is not
required. If the pet is running during the upgrade, quit it first so the
installer can replace the binary.

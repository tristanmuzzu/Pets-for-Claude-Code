# v0.7.3: blocked, not retried

Two changes about the same thing: a number on a card is only worth the space
if you can do something with it.

## The red chip counts what auto-mode blocked

It used to read **N retried** and count tool calls that failed —
`PostToolUseFailure`. That is not actionable. A failed grep means Claude tries
something else and the turn carries on, so the number only ever said "the agent
is having a bad time", in red, on a card whose whole job is to be trusted at a
glance.

It now reads **N blocked** and counts `PermissionDenied`, which Claude Code
documents as *denied by the auto mode classifier*. That is worth a red chip: it
says the permission rules, not the model, are what this turn is fighting — and
that is something you can act on, by approving the thing or by loosening the
rule. It counts per turn and clears on the next prompt.

The expanded log tags the line `blocked`, in the same orange a waiting card
uses. Refused by policy is not the same colour as broken.

Tool failures are untouched everywhere else. The card still says
**Recovering · Grep failed** while it happens, and the log still shows it in
red. Only the tally is gone.

## Work that ends badly still ends

v0.7.0 taught the card to say **Finishing · N running** while the work a turn
started was still going. It counted that work out of the transcript, and it
only ever counted it *back in* on `<status>completed</status>`.

A real transcript ends work four ways. Across one machine's history: 1156
`completed`, 65 `failed`, 22 `stopped`, 10 `killed`. So a single subagent that
failed left the count permanently one too high, and from that moment every turn
in that session read **Finishing · 1 running**, never went green, and never
blinked the tray. The five-minute write-off could not rescue it either: that
clock only starts once the session goes entirely quiet, which a session you are
working in never does.

All four terminal statuses now end the work. `running` deliberately does not —
that notification is a progress report, not an ending.

## Also

- `cargo fmt --check` is a CI step, and `main` had been red on it since
  v0.7.1. Formatted; the check means something again.
- The browser demo (`npm run dev`) still fed the retired `subagents` field, so
  the **3 running** chip was missing from every demo run and from anything
  recorded off one.

## Verified

- Hook path driven with real payload shapes against the built binary: two
  `PermissionDenied` give `blocked=2`, a `PostToolUseFailure` leaves it at 2,
  the next `UserPromptSubmit` resets it to 0.
- `pipsqueak sessions` against a transcript holding two launches and one
  failure reports `outstanding: 1`, not 2.
- 82 Rust tests, 31 JavaScript tests, clippy with `-D warnings`, rustfmt, and
  the sprite-reproducibility check, all green in CI.
- Not re-verified on real hardware for this release: the fresh-install and
  upgrade checklist items. Nothing here touches the installer, the config file
  or the window layer.

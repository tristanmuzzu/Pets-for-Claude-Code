# v0.7.4: waiting is not dying

One bug, in the one claim the overlay exists to make.

## A card that is asking you something never says the session died

The sweep gives up on a session that has been running with no events for five
minutes. Claude Code fires a hook per tool call, so that silence normally means
the turn died without a `Stop`, and the card should stop claiming work is in
progress.

But there is a second thing that produces exactly that silence: **being asked a
question**. A permission prompt fires its hook and then nothing else happens,
because nothing else *can* happen until you answer. So five minutes after you
walked away from a prompt — which is the entire scenario this app was built
for — the card was relabelled **Stopped responding** while still showing the
question underneath it. Two contradictory claims, in one card, about the same
silence.

Only one of them was checkable. A pending prompt is a fact; "stopped
responding" is an inference. So the sweep now leaves a session that is blocked
on a human alone, however long it takes, and the status line prefers the
question over the verdict even if some older state says otherwise. A session
whose agent process has genuinely died is still retired immediately — that
check runs first and is the honest test for it.

`docs/guides/how-it-works.md` has claimed this since it was written: *"A
session that is genuinely waiting on you is never retired by age. That claim
stays true no matter how long you take."* Now it is.

## The release pipeline can no longer ship what CI refused

`ci` runs `cargo clippy -D warnings` and `cargo fmt --check`; the release
workflow did not. That is how v0.7.2 built a green release out of a commit
whose `ci` run was red. Both gates now run before anything is bundled.

The release body also just said "See docs/releases/vX.Y.Z.md". It now contains
the notes, which is what the file was for.

## Verified

- The old bug, reproduced against the installed v0.7.3 build: a session with
  `waiting_since` six minutes old came back `state: idle, stalled: true`. The
  same probe against this build stays `waiting`, with the question intact.
- The decision is now a pure function, `has_stopped_responding`, with tests for
  the waiting case, the pending-permission case, the ordinary-silence case and
  the short-pause case.
- 84 Rust tests, 32 JavaScript tests, clippy, rustfmt and the sprite check.
